# NewMe 可观测性方案 v1.1
## MoA 修订版 · 基于 R1 三模型 + R2 聚合裁决

---

## 一、修订后的目标设定

**核心目标**：建成**以 Sentry 为底座、零新增成本**的可观测性系统，实现**系统先于用户感知故障**。

**量化目标（新增）**：
- **MTTD**（平均检测时间）：< 1 分钟（P0 验收标准）
- **MTTR**（平均修复时间）：< 30 分钟（P2 目标，针对已知故障模式）
- **告警信噪比**：> 70%（有效告警 / 总告警）
- **故障覆盖率**：L0 登录路径 100% 覆盖，核心业务流程（创建/导出/支付）P1 阶段覆盖

**三期演进**：
- **P0（本周，5-8 人天）：有感知** —— 服务端复活 + 基础设施监控 + 拨测 + 告警 + Hermes 高可用底座
- **P1（下周）：可诊断** —— Tracing + 业务指标 + 配额管理 + 告警分级
- **P2（本月）：能闭环** —— 错误预算 + 受控自动修复（只读诊断优先）

## 四、自动修复安全边界（强制约束）

**设计原则**：**只读诊断优先，写操作人工确认，异常自动熔断**

### 1. 操作分级
- **L1 只读诊断**（允许自动执行）：`journalctl` 查询、`df`/`free` 检查、进程列表获取、Git 日志查看、Sentry 错误上下文获取
- **L2 温和操作**（需人工确认）：服务重启、配置重载、缓存清理
- **L3 危险操作**（禁止自动执行）：数据库回滚、数据删除、DNS 切换、防火墙规则变更、成本相关操作（如扩容）

### 2. 配置化开关
```yaml
# /etc/hermes/autofix.yml
autofix:
  enabled: true
  max_auto_level: L1  # 严格限制只读
  require_confirmation_for: [L2]
  forbidden_auto: [L3]
  
  circuit_breaker:
    failure_threshold: 3      # 连续 3 次失败熔断
    recovery_timeout: 600s    # 10 分钟后尝试恢复
    global_kill_switch: true  # 一键关闭所有自动修复
```

### 3. 熔断机制
- **硬熔断**：连续 3 次诊断脚本返回非零退出码或超时，自动关闭 `autofix.enabled`，并推送 "Hermes Autofix Circuit Opened" 告警
- **软熔断**：错误预算耗尽（如 1 小时内错误数 > 100），自动降级为仅告警不诊断，避免诊断本身加重负载
- **人工熔断**：任何工程师可通过命令 `hermesctl autofix pause --duration=2h` 立即暂停自动修复

### 4. 审计与回退
- 所有诊断命令完整记录到 `/var/log/hermes/autofix.log`（命令、输出、时间戳、决策结果）
- 保留最近 10 个版本的配置快照，支持 `hermesctl rollback --to=prev` 一键回退

## 六、冻结规则（≤5 条，不可协商）

1. **🚫 P0 未完成前，禁止启动 P1 自动修复功能**  
   *理由：防止在底座（Hermes/基础设施监控）不稳时叠加复杂逻辑*

2. **🚫 Hermes 未通过单点故障演练前，禁止承担生产环境告警路由**  
   *理由：防止告警静默导致故障无人知晓*

3. **🚫 未建立 Sentry 配额监控前，禁止开启 Session Replay 全量采集**  
   *理由：防止配额瞬间耗尽导致关键错误事件被丢弃*

4. **🚫 未定义告警分级降噪策略前，禁止开启全量告警通道**  
   *理由：防止告警疲劳导致团队忽略关键告警*

5. **🚫 未通过混沌工程演练（人工注入故障验证诊断逻辑）前，禁止开启 L2/L3 级自动修复**  
   *理由：防止自动修复脚本误操作引发级联故障*
