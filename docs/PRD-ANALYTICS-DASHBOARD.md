# PRD: CRM 销售分析面板

---

## 产品定位

给 NewMe 销售团队的分析工具。不同角色看到不同范围的数据，目标一致：**推进业务，减少漏单。**

---

## 角色与权限

| 角色 | 数据范围 | 核心诉求 |
|------|---------|---------|
| CEO（Tanya） | 全公司所有数据 | 判断业务健康度、发现瓶颈、调整资源 |
| Admin | 全公司所有数据 | 同 CEO + 管理操作（分配、转移） |
| Sales（Mohamed/Faheem） | 仅自己名下的线索/报价/合同 | 知道今天该干什么、哪些快丢了、哪些快成了 |

**关键原则：Sales 不需要"全公司视角"，但需要"我的地盘"的完整诊断能力。**

---

## 模块设计

### 模块 1：线索健康度

**CEO 视图：**
- 全公司线索池总览：总数、本周新增、活跃/休眠占比、零跟进占比
- 质量分布：待定/好/坏各多少
- 全公司超期跟进 Top 20 列表（谁的线索、谁负责、超期几天、什么阶段）

**Sales 视图：**
- 我名下线索总览：总数、本周新增、活跃/休眠、零跟进占比
- 我名下质量分布
- **我的超期跟进列表**——这是销售每天打开 CRM 最该看的东西
- 每条超期线索直接可操作：一键打电话/发 WhatsApp/记跟进

**定义：**
- 活跃 = hot/warm 状态，或 7 天内有联系记录
- 休眠 = dormant 状态，或超过 14 天无联系且未成交/未丢单
- 零跟进 = 从未联系过
- 超期 = 应跟进日期已过，或创建超 48h 仍未首次联系

---

### 模块 2：销售负载

**CEO 视图：**
- 每个销售的线索量对比（柱状图）
- 每个人的签约额、转化率、跟进率
- 负载失衡预警：某人线索量 > 平均值 1.5 倍时黄色提示"建议转移"
- 管理员可点"一键平衡"：把超负载销售的未联系新线索轮流分给低负载销售

**Sales 视图：**
- 我的线索总量 + 阶段分布（new/contacted/qualified/quote/won 各多少）
- 我的跟进率（已跟进 / 总线索）
- 我的超期跟进数——红色数字，催我行动

---

### 模块 3：管道漏斗

**CEO 视图：**
- 全公司漏斗：New → Contacted → Qualified → Quotation → Negotiation → Won，每级数量和占比
- 每级→下级转化率，低于 30% 标红（瓶颈）
- 每阶段平均停留天数——太久 = 卡住了
- 点击某阶段跳转线索列表

**Sales 视图：**
- **我的漏斗**：只看我名下线索在各阶段的分布
- 我在哪一步丢客户最多
- 我卡住的线索：在某个阶段停留超过平均 2 倍的线索列表

---

### 模块 4：回款追踪

**CEO 视图：**
- 全公司回款四数字：合同总额 / 已收 / 超期未收 / 本周到期
- 全部分期明细：客户、合同金额、第几期、金额、到期日、状态、超期天数
- 超期标红，7天内到期标黄
- 每个销售的回款表现：签约额 vs 已收 vs 回收率

**Sales 视图：**
- 我名下合同的回款进度
- 我的超期待收款——催收任务
- 我的本周到期提醒

**状态定义：**
- 🔴 超期：到期日 < 今天
- 🟡 即将到期：7天内到期
- 🟢 已付
- ⚪ 待付

---

### 模块 5：广告 ROI

**仅 CEO/Admin 可见。** Sales 不需要看全公司广告投入数据。

- 广告期间总览：总花费、总线索、CPL、转化数、签约额、ROAS
- 按 campaign 拆解：每个 campaign 的花费、线索数、CPL、转化、ROAS
- 来源 vs 质量：每个来源的好/待定/坏占比和转化率

**数据来源：**
- Phase 1：从 COS Excel 导入广告花费数据（`市场投流/` 目录）
- Phase 2：接 Meta Ads API 自动拉取

---

### 模块 6：周度趋势

**CEO 视图：**
- 过去 12 周：每周新增线索、签约额、转化率折线图
- 本周 vs 上周环比变化

**Sales 视图：**
- 过去 12 周：我名下的新增线索、签约额、转化率
- 我的本周 vs 上周

---

## 页面结构

### 入口

侧边栏新增 **Analytics** 菜单项，排在 Pipeline 之后。

### 布局

**CEO/Admin 页面（2 列网格）：**

```
┌──────────────────┬──────────────────┐
│  线索健康度        │  销售负载         │
├──────────────────┴──────────────────┤
│  管道漏斗（全宽）                     │
├──────────────────┬──────────────────┤
│  回款追踪          │  广告 ROI         │
├──────────────────┴──────────────────┤
│  周度趋势（全宽）                     │
└─────────────────────────────────────┘
```

**Sales 页面（单列，聚焦行动）：**

```
┌─────────────────────────────────────┐
│  🔴 我的超期跟进 (12)      ← 最醒目  │
├─────────────────────────────────────┤
│  我的线索健康度                       │
├─────────────────────────────────────┤
│  我的管道漏斗                         │
├─────────────────────────────────────┤
│  我的回款任务                         │
├─────────────────────────────────────┤
│  我的周趋势                          │
└─────────────────────────────────────┘
```

**Sales 页面设计原则：行动优先。** 最上面是"你今天该干什么"（超期跟进），不是数据看板。

---

## 验收标准

1. Tanya 登录 → Analytics → 10 秒内全部模块加载
2. Mohamed 登录 → Analytics → 只看到自己名下数据，超期跟进排最上面
3. 数据与 DB 实际数据一致（每模块抽 3 条对比）
4. CEO 视图超期线索总数 = Sales 各自超期数之和
5. 漏斗各阶段数量之和 = 线索总数（CEO）/ 名下线索总数（Sales）
6. 回款总额 = 所有合同金额之和
7. 移动端不布局错乱

---

## 实施优先级

| 优先级 | 内容 | 理由 |
|--------|------|------|
| P0 | 全部 4 个核心模块（健康度+负载+漏斗+回款），含 CEO 和 Sales 双视图 | 日常决策+推进业务的核心 |
| P1 | 广告 ROI + 周度趋势 | 投放优化和趋势判断 |
| P2 | 自动化（超期通知推送、负载均衡、线索自动评分） | 减少人工操作 |
