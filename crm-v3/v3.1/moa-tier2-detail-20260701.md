# 📌 决策点 3：容错、性能、扩容（增量解析 + 断点续跑 + 快慢模型分流）

## 3.1 现状分析

**事实清单**（来自 P1P1 行 4681-4698 + 行 4937-4940 + 三模型裁决）：

| 维度 | 当前状态 | 痛点 |
|------|----------|------|
| **AI 模型调用** | 硬编码 aiohttp，串行调用 Qwen3-Max / DeepSeek-V4-Pro / GLM-4-Plus（行 4590-4592） | 任意一模型超时/失败，整轮审计回滚 |
| **耗时** | 三模型并行总 71.6s（Qwen 最慢，行 4592），目前 71 个 migration 解析 < 1s | 随文件量增长，三模型总耗时线性增加 |
| **容错** | 无增量解析、无断点续跑、无指数退避（行 4697） | 单次失败即重头跑 |
| **模型路由** | 三模型一视同仁，未按"快/慢/便宜"分流 | 简单审计也调全量模型 |
| **审计规模** | 当前 71 个 migration；裁决"200+ 文件前完成即可" | 扩容窗口期 |
| **优先级分歧** | Qwen/GLM：Tier 2 / DeepSeek：Tier 1（行 4690-4694） | **裁决：Tier 2**（P1P1 行 4696 已拍板） |

**核心痛点（一句话）**：71 文件时可接受，200+ 文件时三模型串行 + 无断点的现状会变成"半失败的审计"——要么白跑 30 分钟，要么漏掉关键判定。

## 3.2 方案 A / B / C 对比

| 维度 | **方案 A：增量解析 + 断点续跑 + 快慢分流**（裁决推荐） | **方案 B：纯异步 + 指数退避** | **方案 C：完整容错 + 全量重试 + 模型池** |
|------|------------------------------------------|----------------------------|----------------------------------|
| **核心机制** | 按文件 hash 增量解析；manifest.json 记录已完成文件；快模型（GLM-4-Plus）走 fast lane / 慢模型（Qwen3-Max）走 slow lane | 所有任务统一进 asyncio.Queue + 指数退避（1s/3s/9s），失败 3 次后入 dead-letter | 增量 + 断点 + 异步 + 模型池（每模型多副本并发限速） |
| **重试** | 最多 2 次指数退避（参考 P0-1 超时方案） | 最多 3 次指数退避 | 最多 5 次 + 永久 dead-letter 持久化 |
| **失败回放** | 续跑时跳过 manifest 中 ✅ 文件，⚠️ 重跑 | 重头跑全量 | 续跑跳过成功，按 dead-letter 队列重放 |
| **模型路由** | 按 prompt 长度 / 任务复杂度自动分到 fast / slow | 所有模型无差别调用 | 5 模型 × N 并发，受速率限制 |
| **成本（人天）** | **6-7 人天**（裁决行 4698） | 3-4 人天 | 12-15 人天 |
| **200 文件耗时估算** | ~40s（fast lane 跳过大量）+ 增量 200 文件新增 ~5s | ~120s（全量重跑一次） | ~30s（模型池并行） |
| **优点** | 裁决三模型一致推荐；符合 P0-1 超时/重试风格；可平滑从 71 → 200+ | 实现最简单 | 性能最强 |
| **缺点** | 增量逻辑需处理 manifest 一致性；快慢分流需先标定 prompt 复杂度 | 重跑成本仍高，未根治 | 复杂度高，人天投入超裁决 2 倍 |
| **优先级** | **Tier 2**（裁决拍板） | Tier 2-3 | Tier 3 |
| **触发条件** | 文件数 ≥ 150 或平均审计耗时 ≥ 90s 时启动 | 现在就做 | 文件数 ≥ 500 时启动 |

5. **快慢分流与本项目 AI 网关（决策点 1 已收）天然兼容**—— 决策点 1 的统一 AI 网关已实现模型路由基础，方案 A 复用其路由能力。

**推荐：方案 A（CI 检查 + 模板生成器 + 可选 Git Hook）**

**理由**：

1. **裁决一致**（P1P1 行 4720）：「CI 检查 + 模板生成器为必做项，Git Hook 为可选项（团队规模 < 5 人时 CI 足够）」—— 这是三模型分歧的**官方折中拍板**。

5. **成本匹配现状**（4-5 人天 vs 裁决预算 4-5 人天）—— 零偏差。
6. **优先级 Tier 2** 与决策点 3 同步—— 可合并 Phase 2（行 4733-4734）一起立项。

### 2. 决策点 4 — 跨团队统一约束（CI 检查 + 模板生成器 + 可选 Git Hook）

**强制规范**：
- ✅ CI 检查 3 项：命名（`{domain}_YYYYMMDD_{desc}.sql` + P0/P1/P2）/ 字段存在性（联动 §3A service_role）/ 输出目录（`/audit/reports/{date}/{task_id}.json`）
