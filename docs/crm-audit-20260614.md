### Round 4 — 业务逻辑 + 工作流（✅ 已完成，亲手实锤）

> 验证方法：直查生产库 quotations/contracts/payments/installment_plans/notifications 表 + 源码 `quotations/generate/route.ts`、`[id]/convert/route.ts` 逐行。

#### 生产数据快照（2026-06-15）
- quotations：**2 条**（draft×1 + sent×1），`contract_id` 全 NULL
- contracts：**0 条** | payments：**0 条** | installment_plans：**0 条**
- → **整条变现链路（报价→合同→回款）在数据层面完全没跑通**

#### 🔴 P0-1：报价生成不回写 `leads.quotation_value`（Pipeline 永远为 0 的根因）
- 源码实锤：`quotations/generate/route.ts` L166-175，报价保存后只 `update stage`，**无 `quotation_value` 字段**
- 生产数据佐证：已生成报价的 2 个 lead（total 7972.02 + 7792.47 AED），`quotation_value` 仍为 **NULL**
- 后果：Dashboard PIPELINE VALUE / 加权管道 / Sales Leaderboard 金额 **永远 AED 0**，与 Round 3 P0-1 互为印证
- 修复：generate + convert route 补 `.update({ quotation_value: total_amount, currency })`，并对存量 2 条报价批量回填

#### 🔴 P0-2：报价状态机断头路（draft/sent → accepted 无入口 → 0 合同 0 回款）
- 现状：2 条报价 status = `draft`(1) + `sent`(1)，**0 条 `accepted`**
- `convert/route.ts` L43 强制要求 `status='accepted'` 才能转合同
- **但全代码库无任何地方把 quotation 从 draft/sent 改成 accepted**（grep 确认）
- 状态机：`draft → sent → ❌（断头）→ 永远到不了 accepted → 合同转不了 → 0 合同 → 0 回款`
- 后果：即使销售反复跟单，系统永远无法推进到合同环节，变现链路死锁
- 修复：增加 quotation status 转换 API（`/api/quotations/[id]/status`，支持 sent→accepted + accepted→rejected），前端报价详情页加"标记为已接受"按钮

#### 🟡 P1-1：线索 stage 与报价状态脱节
- 实测：报价 sent 的 lead `a08c0b22`，其 stage 仍是 `new`；报价 draft 的 lead `6e26ee6f`，stage 是 `contacted`
- generate route L166 虽有 `.update({ stage: 'quotation_submitted' })`，但这两条报价（06-10 创建，早于 06-12 迁移修复）当时未执行该更新
- 后果：线索流转与报价状态不同步，sales 看板线索分布失真
- 修复：对存量 2 条报价补 `stage='quotation_submitted'`；后续 generate route 已有更新逻辑
