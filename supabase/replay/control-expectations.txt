# scripts/replay-migrations.sh MODE=control applies supabase/replay/01_floor_schema.sql
# and the behaviour fixtures WITHOUT the branch migrations, then runs
# supabase/replay/10_assert_release_contracts.sql with `replay.collect = on` and
# hands the log to scripts/control-marker-accounting.mjs together with this file.
#
#   fail  the assertion is load-bearing: it MUST emit exactly one
#         `ASSERT_FAIL <name>` against the un-remediated floor. If it passes
#         there, it is a tautology and proves nothing about the migration.
#
#   pass  the assertion holds against the floor by design, and the reason is one
#         of four:
#           - an outage detector (F-09 / F-10 leg 2: `authenticated` and
#             service_role must KEEP grants the reviewed revision revoked, which
#             would have taken ten call sites offline);
#           - an F-02 "do not delete the identity" invariant;
#           - a fixture precondition, describing the seed rather than the release;
#           - the paired half of a behaviour assertion — "the refusal left the row
#             alone", "the fixture was rolled back", "the unrelated lock was not
#             taken". On the floor the action under test does not happen at all, so
#             nothing changed; the load-bearing half of the pair is the SQLSTATE.
#
# Why this file exists at all, rather than a list inside the shell script
# ----------------------------------------------------------------------
# Round-3 finding P1-12. The control used to check two things: that each declared
# name appeared somewhere in the assertion file, and that no `ASSERT_OK <name>`
# line was observed for it. The second is satisfied by an assertion that never
# ran — and 78 of them never ran, because a DO block that hit undefined_function
# against the floor aborted and silenced every assertion below it. CI reported
# "100 load-bearing assertions all fail without their migration" while the log
# held 87 assertion-specific failure markers and 40 unclassified SQL errors.
#
# The accounting is now exact and one-to-one in both directions: this file and the
# assertion file must declare the same set of names, every name must produce
# exactly one marker, every marker must match its declared verdict, and the
# control log must contain no unclassified SQL error at all. The gate itself is
# mutation-tested by tests/release/control-marker-accounting.test.mjs.
#
# Adding an assertion means adding a line here. There is no default: an
# undeclared name fails the run, and so does a declared name with no assertion.
# ============================================================================
